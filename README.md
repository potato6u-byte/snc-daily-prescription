# SNC 데일리 온도처방 (snc-daily-prescription)

신앙촌 발효유 **런(RUN) 공정**의 일일 온도 처방 도구입니다.
**전날(들)의 공정결과 값을 확인하고, 오늘의 온도처방을 자동 산출**합니다.

- 데이터 근거: 현장 로우데이터 **278배치 (2025-07-01 ~ 2026-07-30)** 실측 재적합
- 문서 근거: 부산 신앙촌 허브 · 「신앙촌 데이터 관리 컨설팅 최종 보고서」 및 FermaAX 작업
- 스택: Python 3.10+ / Streamlit / SQLite / pandas · openpyxl

## 무엇을 하는가

```
[전일 실적 입력]  현장 양식 엑셀 업로드  또는  핵심 항목 직접 입력
        │
        ├─ 종결시간 잔차  →  최근 EWMA  →  오늘 살균냉각 보정
        └─ 이송온도 잔차  →  센서·배관 추세 감시
        │
[오늘 환경 입력]  탱크 · 배치량(톤) · 새벽 실내온도 · 접종 실내온도 · 실외온도
        │
        ▼
[오늘의 온도처방]  살균냉각 설정 / 핫워터 설정
                 예상 이송후 유입온도 · 종결분 · 산도차 · 종결산도 · 5H산도 · pH
                 현행 겨울 관행 대비 기대 개선량
```

## 데이터에서 확정한 모델 (278배치 재적합)

| 관계 | 회귀식 | n | r² | se |
|---|---|---|---|---|
| 이송 하락폭 ~ 새벽 실내온도 | `y = 2.4385 − 0.07842 x` | 277 | 0.614 | 0.36℃ |
| 종결분 ~ 살균냉각온도 | `y = 795.263 − 10.7878 x` | 278 | 0.473 | 14.1분 |
| 산도차 ~ 살균냉각온도 | `y = 0.3817 − 0.00692 x` | 278 | 0.282 | 0.0137 |
| 종결산도 ~ 살균냉각온도 | `y = 0.7479 + 0.0058 x` | 278 | 0.497 | 0.0072 |
| 5H산도 ~ 살균냉각온도 | `y = 0.3662 + 0.0127 x` | 278 | 0.528 | 0.0149 |
| 핫워터설정 ~ 새벽 실내온도 | `y = 39.0351 − 0.0224 x` | 277 | 0.360 | 0.173℃ |

**기준선 재현** — 핫워터·살균냉각 38.5℃로 운전한 43배치 실측 평균:
산도차 **0.1162** · 종결분 **382.9분** · 접종 실외온도 **27.0℃**
(허브 보고서의 기준선 0.116 / 382.9 / 외기 약 27.6℃와 일치)

**골든군** — 종결분 375~385 & 산도차 0.110~0.120 구간 48배치 실측 평균:
종결분 379.5분 · 산도차 0.1162 · **종결산도 0.9702** · **pH 4.699** · 이송후 38.94℃

### 핵심 발견 — 지배 변수는 살균냉각온도

발효 결과(종결분·산도차·종결산도·5H산도)는 **이송후 탱크온도보다 살균냉각온도에 더 강하게 붙습니다.**
살균냉각을 기준선 **38.5℃로 고정**하면 계절과 무관하게

```
종결분 379.9분 · 산도차 0.1153 · 종결산도 0.9712   ← 골든 목표(380분 / 0.116) 재현
```

반면 현장의 **겨울 보상운전(살균냉각 40.69℃, 101배치)** 은 종결분 355.6분 · 산도차 0.1005로
기준선에서 이탈합니다. 겨울철 이송 손실을 과다 보상해 유입온도를 39.9℃까지 끌어올린 결과입니다.

→ 그래서 기본 처방은 **살균냉각 38.5℃ 고정 + 종결시간 잔차 보정**입니다.
보고서의 연쇄 구조(목표 유입온도 + 예상 하락폭)를 따르는 **이송 보상 모드**도 선택할 수 있지만,
회귀 적합도는 기준선 고정이 더 높습니다(r² 0.473 vs 이송후 단독 0.369).

### 잔차 보정 (피드백)

- 종결시간 잔차(실측 − 처방)의 EWMA(α=0.5) → `냉각보정 = −잔차 / 10.79`, 범위 ±0.5℃
- 이송온도 잔차는 **감시용**입니다. 303호는 301/302 대비 이송 온도차가 **+0.51℃** 커서
  센서 교정·이송경로 점검 권고가 자동 표시됩니다.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py          # Windows: run.bat
```

기본 주소 `http://localhost:8501`, SQLite 파일은 `snc_prescription_history.db`에 생성됩니다.

## 입력 양식 — 현장 양식을 그대로 사용

`examples/SANC_A300_온도_입력양식_예시.xlsx` 또는 앱의 **[빈 입력 양식 내려받기]** 로 받습니다.

- 시트 `T300온도`, 5행 그룹 헤더 / 6행 열 헤더 / 7행부터 데이터 — **현장 양식과 동일한 62열 구조**
- `날짜 · 300탱크 · 제품 이송후 탱크온도 · 새벽/접종/9시~종결 실내온도(습도) · 실외온도 · 당일 날씨
  · 발효탱크TT · 살균유/1H/5H 측정온도 · 발효실 실내온도 · 살균냉각온도 · 핫워터설정온도
  · 산도(살균후/접종후/1차샘플/종결분/종결/산도차/분당산도/시간/총이송/서지/완제품)
  · 점도 · PH · 당도`
- 열 이름·순서가 같으면 그대로 인식합니다. 중복 열 이름(종결·서지1·완제품1 등 4개 그룹)은 **등장 순서**로 구분합니다.
- 영문/축약 헤더(`batch_date`, `살균냉각온도`, `종결분` …)도 함께 인식합니다.
- `미측정 · 미기록 · - · N/A` 등은 조용히 건너뛰고, `16..7` · `비/맑음` 같은 **실제 기입 오류는 경고로 표시**합니다.
  (원본 278배치에서 8건 확인)
- 기존 양식의 모든 열은 `raw_json`으로 원형 보존되며, 조회·처방에 쓰는 핵심 열만 별도 컬럼으로 저장합니다.

## 화면 구성

1. **① 전날 공정결과 확인** — 현장 양식 업로드 / 핵심 항목 직접 입력 / 실적 이력 / 기입 오류 경고
2. **② 오늘의 온도처방** — 환경 입력 → 처방 계산 → 근거 회귀식 → 현행 관행 대비 → 처방서(.xlsx)
3. **③ 이력 · 모델검증** — 처방 이력, 종결시간 오차 추이(ME/MAE), **로우데이터 재적합 검증**

### 모델 검증 탭

로우데이터 원본(`통합데이터.xlsx` 등)을 올리면 계수를 **다시 계산해** 내장 값과 나란히 보여줍니다.
내장 계수와 일치하면 모델이 그 파일에서 산출된 것임을 그 자리에서 확인할 수 있습니다.

## 저장소에 원본 데이터를 넣지 않습니다

로우데이터(품질관리일보)는 사내 자산이므로 이 저장소에 포함하지 않았습니다.
`examples/`의 예시 3행은 **구조 설명용 합성값**입니다. 원본은 앱의 [모델 검증] 탭에서 직접 올려 쓰십시오.

## 알려진 한계

- 이송 하락 회귀는 배관·이송시간·수량 조건을 반영하지 않는 평균적 관계입니다(보고서 한계 절).
- 새벽 실내온도 관측 범위는 **15.8 ~ 37.7℃**이며, 벗어나면 처방 신뢰도가 `낮음(외삽)`으로 표시됩니다.
- 종결분 예측 se는 14.1분, 산도차 se는 0.0137로 배치 단위 산포가 큽니다. 단일 배치 판정이 아니라 추세 관리에 쓰십시오.
- 종결 pH 회귀는 r²=0.047로 사실상 무의미해 참고값으로만 표시합니다.
- 최적 설정값의 인과 검증은 허브 보고서 1~3단계(수집 표준화 → 모니터링 자동화 → 보정량 규칙화)에서
  축적되는 데이터로 확정해야 합니다.
